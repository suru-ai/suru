# Deliver Subagent Reports as Provider input, and give a brokered Subagent its own Provider actor

When a brokered Subagent's Turn settles, Suru delivers a Subagent Report — its outcome and a bounded excerpt of its final Message — to the delegating Agent as that Agent's Provider's own input: a stream-json user message for Claude, `turn/start` for Codex when its Agent is idle and `turn/steer` pinned to the running turn when it is working, and `session.send` in immediate mode for Copilot. An idle Agent wakes into a Continuation; a working Turn is steered. This is the pattern Claude and Copilot use for their own background subagents, whose completion notifications start a new turn in an idle parent; Codex never starts a parent turn itself, offering only a blocking `wait_agent`, so Suru supplies the wake-up for it. A bounded `wait_subagents` Tool stands beside the Report for an Agent that needs a result before it can go on. A brokered Subagent is a full Session with its own Provider actor, because its Provider differs from the root's: today one actor per root Session routes interrupt, stop, Approvals, posture delivery, and Continuation-owing through native Subagent routes only, and each of those paths becomes tree-generic so a brokered child is stopped, answered, and continued like a native one.

## Considered Options

- **Blocking only.** Rejected: a spawn that blocks for an hour is hostage to three harnesses' tool timeouts, and the parent can do nothing meanwhile.
- **Push only.** Rejected: Codex's models are trained on `wait_agent` and would poll a status Tool in a loop.
- **Running the child through the root's actor.** Impossible across Providers, and it is why the root-only routing has to open up.
- **Attributing a spawn by correlating it with the projection's tool_use stream.** Rejected for the reason ADR 0032 refused it for Claude steers: it matches on timing and arguments.

## Consequences

- A Report stands nowhere in any Transcript; the settled Subagent row is the record, and the child's own Transcript holds its words. The row is added by the Broker at spawn, in the caller's active Turn, and each Provider's projection absorbs the Broker's tool calls rather than showing them.
- A Report whose Agent has no Provider process waits for the head of that Session's next Turn; Suru never relaunches a Provider to deliver one. A Report delivered to a Session the user had settled makes it active again.
- A brokered child the user stops on its own is reported as stopped; an interrupt of the parent stops its children and reports nothing. A brokered child keeps working when its parent's Provider process ends.
- A Report to a settled native Subagent wakes a Continuation of that Subagent's own Session, as a Watch would.
- A Report reaches the Provider as input beside a Prompt, never as a Message: the Turn input a start or steer carries holds the Reports at its head and then the Prompt or Delegation, or the Reports alone for the Continuation one wakes. The Report is rendered once, in Suru's words, so every harness sends the same text: the Subagent's name and session_id, how its stretch settled and after how long, and at most 4000 characters of its final Message, naming `read_subagent` for the rest.
- A Report reaching a working Codex Turn goes as the harness's own steer, `turn/steer` pinned by `expectedTurnId`, rather than as `turn/start`: the harness holds a single native Turn slot that a `turn/start` claims, and a `turn/start` mid-Turn would carry that Turn's settings overrides into it. A steer the Provider no longer takes — its Turn ended before Suru heard — leaves the Report waiting, and it wakes the Agent once the Turn settles. A Report that wakes an idle Codex Agent goes as `turn/start`.
- Held Reports live in memory. A restart loses one still waiting; only a stretch the next start repairs is reported afresh, as failed with no duration and no excerpt (ADR 0029), and held for the parent's next Turn in that process.
- A Report to a native Subagent goes through a Provider-seam route to that Subagent by identity. No harness offers one yet, and a refused Report is dropped, since no later Turn of a native Subagent's is Suru's to begin; a native Subagent first becomes a delegating Agent when its Broker calls are attributed to it (#420).
- A spawn is attributed to the Session its token names unless the call names its caller more exactly, and when the Session it is attributed to has no active Turn a Continuation is begun to hold the row. Codex's calls do, through `_meta.threadId`, so its spawns are attributed exactly. Claude's calls carry `_meta["claudecode/toolUseId"]`, the id of the calling `tool_use`, which the projection already places under a native Subagent by `parent_tool_use_id`. Joining the two would attribute by identity rather than the timing and arguments rejected above, but it runs through the projection's tool_use stream, which spec #407 keeps out of scope, so a native Claude Subagent's spawn stays with its token's Session until a later spec adopts the join. Copilot's calls carry no such signal, so a native Copilot Subagent's spawn stays with its token's Session (`docs/validation/0408-subagent-mcp-attribution.md`).
- A Continuation begun to hold a spawn's row settles as it is begun, as ADR 0033's does: that Session's Provider never learns of it, so nothing else would settle it, and the row works on past it with the child.
- Output a Provider sends with no Turn active while a brokered Subagent its Agent delegated to works, or after one settles, is owed to it and placed in a Continuation only until the owner's next stretch of work begins or an interrupt reaches the owner's work, at parity with native routes, so an interrupted stream's trailing output opens no Continuation that nothing would settle. A stretch the interrupt stopped from above is owed nothing either, since its delegating Agent hears nothing of it.
- A Report and that owed output meet in one rule: a Report's Continuation begins the stretch that answers the settle it reports, so the debt only places output where no Report reached the Provider. A Continuation opened for late output is no Turn its Provider began for Suru and takes no steer, so a Report arriving while one is open waits and wakes the Agent once it settles, unless a Prompt settles it first and carries the Report at the head of its Turn.
- The wait Tool defaults to 60 seconds, bounded to 10 and 600, with progress every 30 seconds, and returns `timed_out` so the Agent may call again.
- Broker Tools never raise an Approval: Claude allowlists `mcp__suru__*`, Codex's per-thread config sets the server's default approval mode to approve, and Suru's own Copilot handler approves the server — except a request Copilot marks as needing an explicit human decision under a managed policy, which takes the path any such request takes, since approving it would override the organization's policy.
