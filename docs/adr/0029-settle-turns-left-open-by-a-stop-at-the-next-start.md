# Settle Turns left open by a stop at the next start, and close the Provider gate only after the Providers

ADR 0024 has restoration trust durable Turns: a restored Session is at work only where a Turn says so. That trust was wrong for one class of Turn. When the server stops, `ShutdownController` closes the `ProviderUpdateGate` as its first act, so the `fail_all` settlement each Provider actor writes as its process dies is silently dropped; the child Session's prompt-less Turn stays `Active` in the database, and at the next start the parent reads "Waiting for subagents" forever because its Working is derived from that open child interval (ADR 0015). We now do two things. Hydration settles every Turn — root or child — that is still open when Suru starts: the Turn Settles as `Failed` with `settled_at` at its `last_output_at` (or `started_at`), an `Error` Activity naming the server stop, in-flight Activities settled, and, for a child, the spawner's `subagent` Activity marked `Failed` with no duration — the same record `fail_all` writes, produced by the same `fail_turn` writer, committed through the store so it reaches disk. And `Server::shutdown` closes the gate only after the Providers have shut down and before the storage writer stops, so a clean stop settles its own work and restoration is the guard for crashes and for histories written before this change.

## Considered Options

Keeping the child Session `Active` and having the parent's Working derivation ignore child Turns with no live route was rejected: it hides the indicator while leaving the child permanently Working in listings and Usage aggregation, contradicting "Working applies at every depth". Settling only child Turns and continuing to trust a root's open Turn was rejected because no Provider process survives a restart for either, nothing in restoration resumes an open Turn, and one rule is cheaper to hold than two. Settling as `Interrupted` was rejected because Interrupted means a user or interrupt path stopped the work and drives the Working Indicator's guidance.

## Consequences

Restoration is no longer purely a derivation: hydration commits durable changes on the same path that withdraws stranded Prompts. Every history is deferred at startup, so the durable repair lands when a tree is first hydrated; until then the startup projection reads an open Turn as ended at its last output and the Session as Idle, so a listing never reports Working or Active for work no process is doing. A stopping server now writes the settlements the restart used to derive, so the two must read alike: the Approvals and Questionnaires a stop abandons settle as Unavailable, or DeliveryUncertain for a decision in delivery, exactly as the restart recovery reads them, rather than as a Turn that merely ended. A settlement is the one change allowed to carry its own moment through the commit clock, and an Error Activity is no longer output evidence, since neither a live failure nor a repair is the Turn at work. A Turn open when Suru stops is reported as failed, never resumed; a Continuation after restart begins a new Turn.
