# Prefer native rich Clipboard delivery

For formatted copies from Agent Messages and visible Reasoning, offer HTML and the selected Markdown text alternative together through the native Clipboard, falling back to terminal text only when native delivery fails, is unavailable, or exceeds a bounded deadline. This is the rich-copy exception to the always-write-both policy of #274, approved in #287: a terminal Clipboard write can reach the same destination and replace successfully delivered HTML with text. Plain-text-only copies, including Invites and other selectable surfaces, still write both routes; Linux primary selection receives text independently of Clipboard success.

The same selected Markdown fragment supplies both representations, with Code Block-only copies retaining raw code text. HTML contains deliberately generated formatting, escaped literal markup, safe links, and image references presented as links rather than resource-loading elements. The existing lazy worker owns the long-lived native handle and one replaceable pending copy; each copy's completion belongs to its own fallback receiver, so a superseded failure cannot trigger a stale terminal write. Fallback waits asynchronously for at most 250 milliseconds, injectable in tests, and exit checks the latest result after the worker's bounded shutdown without waiting another deadline. A native call already in flight cannot be cancelled: fallback bounds the client's wait, not the platform call, and a late native completion may still claim the native Clipboard.

Native success is best effort according to arboard's delivery result, not a promise that a destination supports HTML, that rich content reaches the reader's machine over SSH, or that content persists after Suru exits. Over SSH, successful native delivery can target the remote machine and suppress terminal delivery to the local machine; that is an accepted limit of preserving native formatting, not a reason to restore a competing terminal write. Persistence depends on the platform's Clipboard ownership and any Clipboard manager. Native and terminal failures remain Log-only.
