# Preview Attachments through terminal graphics probed at startup, Kitty first, drawn only when whole and uncovered

Thumbnails of Attachments in the composer and beneath user Messages are drawn through ratatui-image over ratatui's cell-skip diffing, choosing the Kitty graphics protocol, then iTerm2 inline images, then Sixel, and never half-block mosaics: a preview is either a picture or the dimmed text line that stands in for it. Which protocol the terminal speaks is learned from a probe sent with the existing startup color probe, the Kitty graphics query, XTVERSION, and primary device attributes, plus the cell pixel size, and never from an environment allowlist, except for iTerm2, which has no query. The Setting `transcript.imagePreviews` is on by default because support is probed rather than guessed.

Kitty comes first because its Unicode placeholders let the terminal move and clip images as it moves text, and because it is lossless; Sixel comes last because it quantizes colors. A strip is drawn only when all of its rows are inside the viewport and no Sidebar, Aside, picker, or dialog covers them, and otherwise its rows are left blank at their reserved height so the layout never jumps: iTerm2 and Sixel cannot clip, and any cell written over an image corrupts it, so one rule covers all three protocols and Kitty's source-rectangle clipping is left as a later optimization. No preview is drawn under tmux or screen, or when the cell pixel size is unknown. The client makes thumbnails itself, fetching bytes by id and decoding with the `image` crate limited to the four admitted formats, so the Server stays free of pixel work.
