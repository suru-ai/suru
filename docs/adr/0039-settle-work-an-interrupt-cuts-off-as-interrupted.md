# Settle work an interrupt cuts off as Interrupted, and everything else a Turn closes as Failed

When a Turn settled, every Activity still Active under it — a Command, Tool Call, File Change, or Reasoning block — used to settle as `Failed`, and the TUI told an interrupted Command from a refused one only by its missing exit status. Claude and Copilot never recorded an exit status, so every failed Command on those Providers read as interrupted and folded its error away, and a Tool Call had no signal at all (#437). We now widen `ActivityStatus::Interrupted` beyond Subagent and Watch Outcomes: an Activity still running when its Turn is interrupted settles `Interrupted`, whatever the Provider. An Activity still running when a Turn settles in any other way — failed, repaired after a server stop (ADR 0029), or completed with work its Provider never answered — settles `Failed`, as does one whose Provider reports it failed. So `Interrupted` keeps the meaning ADR 0029 gives it, that someone asked the work to stop, and `Failed` means the work went wrong. Presentation reads the status directly — a Failed Command or Tool Call opens at its Peek, and a Group counts its failed and stopped members apart — and an exit status is only ever the exit code, never a stand-in for why a Command settled.

## Considered Options

Settling everything a Turn closes as `Interrupted`, whatever the Turn's outcome, was rejected: it stretches the word to "cut off" and contradicts ADR 0029, which refused `Interrupted` for a Turn no one asked to stop. A per-Command flag distinguishing refused from interrupted, as #437 first suggested, was rejected because it fixes Commands alone and leaves Tool Calls and Reasoning with the same ambiguity.
