# Hydrate Session histories on access

Deferred Session histories remain owned by SQLite: a Session whose durable metadata is loaded but whose history is not. Startup reads Session rows and batches durable Turns, which carry the small metadata needed to reconstruct Working intervals, latest-Turn Standing, and subtree Usage/Cost. Prompts, Messages, Activities, and Provider-opaque Resume State are decoded only on access. This supersedes ADR-0006's assumption that every history is canonical in memory throughout the server lifetime; once hydrated, the in-memory history is canonical, and storage follows it through saves encoded from that one copy — what each commit moved, noted beside the record, landing at idle moments and at every Turn boundary.

A Session tree is the hydration unit because mutations reconcile Working, Usage, and Questionnaire state across ancestors and descendants. An asynchronous gate coalesces first access; database reads run on blocking tasks outside the store lock. Installation rechecks existence under the store lock, so deletion cannot resurrect state, and notes beside each record that storage holds it as read before any mutation can publish. Reads, subscriptions, commands, Prompt identity checks, and external output admission enter this boundary. Shutdown drains requests before shutting down the writer. Merely listing or deleting Sessions does not hydrate their content, so a listing carries a deferred Session's stored readings as they were last written.

Hydration is also where a history catches up with the process that loads it: Turns left open by a stop settle, undeliverable Prompts withdraw, and an unpinned Approval Posture follows the Settings in force, recorded as applied because a deferred Session has no Provider actor to owe it to: none survives a restart, and eviction stops a tree's actors before it lets the tree go, so the next actor starts under that posture. A Settings change refreshes only hydrated Sessions; deferred ones catch up when they hydrate.

Malformed Session/Turn metadata is isolated at startup. Malformed content or Resume State is isolated on first access: the affected Session becomes unreadable, its root listing is invalidated, and readable subtree projections are recomputed. Child identity is retained for parent-owned deletion, and an unreadable child never becomes a listed root. Schema migrations and newer-schema refusal remain on the readiness path.

We chose targeted Turn loading over a persisted summary projection to keep recovery derived from the same durable facts as live state without a migration/backfill or a second consistency contract. Startup therefore still scales with Turn count, but not Transcript content size. Hydrating a whole tree trades first-open latency and memory for simpler, coherent subtree mutation; per-child hydration is deferred. A tree is also the eviction unit: once nothing holds it — no subscriber, no work running or owed, nothing reading it back would move — and everything it owed storage has landed, a tree idle long enough has its Provider actors stopped, as a restart stops them, and returns to the deferred state, hydrating again at its next access and resuming its conversations from their Resume State at its next Turn. What the process knew of it beyond its history — the operations it answered, and how each of its Prompts was admitted — stays on the record and the Prompt index, so a retry within the process is answered as before the eviction. The writer holds no history copy: saves are encoded from the store's own records, and clean hydration alone never writes recovered state.
