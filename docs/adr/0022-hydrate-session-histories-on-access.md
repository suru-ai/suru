# Hydrate Session histories on access

Unopened Session histories remain owned by SQLite. Startup reads Session rows and batches durable Turns, which carry the small metadata needed to reconstruct Working intervals, latest-Turn Standing, and subtree Usage/Cost. Prompts, Messages, Activities, and Provider-opaque Resume State are decoded only on access. This supersedes ADR-0006's assumption that every history is canonical in memory throughout the server lifetime; once hydrated, the existing canonical store and write-through mirror remain in force.

A Session tree is the hydration unit because mutations reconcile Working, Usage, and Questionnaire state across ancestors and descendants. An asynchronous gate coalesces first access; database reads run on blocking tasks outside the store lock. Installation rechecks existence under the store lock, so deletion cannot resurrect state, and seeds the writer with a complete, clean snapshot before any mutation can publish. Reads, subscriptions, commands, Prompt identity checks, and external output admission enter this boundary. Shutdown drains requests before shutting down the writer. Merely listing or deleting Sessions does not hydrate their content.

Malformed Session/Turn metadata is isolated at startup. Malformed content or Resume State is isolated on first access: the affected Session becomes unreadable, its root listing is invalidated, and readable subtree projections are recomputed. Child identity is retained for parent-owned deletion, and an unreadable child never becomes a listed root. Schema migrations and newer-schema refusal remain on the readiness path.

We chose targeted Turn loading over a persisted summary projection to keep recovery derived from the same durable facts as live state without a migration/backfill or a second consistency contract. Startup therefore still scales with Turn count, but not Transcript content size. Hydrating a whole tree trades first-open latency and memory for simpler, coherent subtree mutation; eviction and per-child hydration are deferred. The writer retains a second history copy only for accessed/new Sessions, and clean hydration alone never writes recovered state.
